# 用户资料修改接口文档

| 文档属性 | 内容 |
| --- | --- |
| 适用模块 | 用户账号与个人资料 |
| 更新日期 | 2026-11-13 |
| 涉及代码 | `src/routes/user.js`、`src/services/user-service.js`、`src/db/queries.js` |

## 1. 通用约定

- 以下接口均需在请求头携带 `Authorization: Bearer <token>`。
- `userId` 由后端从 JWT 的 `sub` 解析，作为定位标识，**不可通过请求体传入或修改**。
- 响应统一使用业务包裹结构：

```json
{ "code": 0, "success": true, "message": "ok", "data": { } }
```

## 2. 字段归属

| 用户可改字段 | 数据库列 | 所在表 |
| --- | --- | --- |
| phone | `phone` | `users` |
| nickname | `nickname` | `user_profiles` |
| avatar | `avatar` | `user_profiles` |
| birthday | `birthday` | `user_profiles` |
| gender | `gender` | `user_profiles` |
| password | `password_hash` | `users` |

以下字段**不开放给用户修改**：`real_name`（实名认证，暂不接入）、`identity_card`、`user_type`、`user_status`、`is_deleted`、`user_no`、`username` 及时间戳字段。

## 3. 修改个人资料

```
POST /api/v1/user/profile
Content-Type: application/json
Authorization: Bearer <token>
```

请求体（支持部分更新，未传的字段保持不变）：

```json
{
  "phone": "13800000000",
  "nickname": "测试用户",
  "avatar": "https://cos.example.com/avatar/xxx.jpg",
  "birthday": "1995-06-15",
  "gender": 1
}
```

### 3.1 校验规则

| 字段 | 校验规则 | 失败返回 |
| --- | --- | --- |
| phone | 非空时须匹配 `^1[3-9]\d{9}$`；且不得被其它账号占用 | 400 `手机号格式不正确` / 409 `手机号已被其他账号使用` |
| nickname | trim 后不能为空 | 400 `昵称不能为空` |
| avatar | 见下方「头像 URL 校验」 | 400 对应提示 |
| birthday | 非空时须匹配 `^\d{4}-\d{2}-\d{2}$`（YYYY-MM-DD）；空值存 `null` | 400 `生日格式应为 YYYY-MM-DD` |
| gender | 必须为 `0`（保密/未知）/`1`（男）/`2`（女）；空值存 `null` | 400 `性别取值应为 0/1/2` |

### 3.2 头像 URL 校验

头像采用 **URL 方案**：前端先裁剪图片并上传到对象存储（如腾讯云 COS）拿到 URL，再把 URL 作为 `avatar` 传入本接口。

| 校验项 | 规则 | 失败返回 |
| --- | --- | --- |
| 格式 | 必须是合法的 `http://` 或 `https://` URL | 400 `头像必须是有效的 http/https URL` |
| 长度 | 最长 500 字符（对齐 `avatar` 列 `VARCHAR(500)`） | 400 `头像地址过长（最多 500 字符）` |
| 空值 | 允许空串，表示清除头像 | — |

### 3.3 响应数据

```json
{
  "user_id": 1,
  "phone": "13800000000",
  "profile": { "user_id": 1, "user_no": "U000001", "nickname": "测试用户", "real_name": null, "identity_card": null, "avatar": "https://cos.example.com/avatar/xxx.jpg", "gender": 1, "birthday": "1995-06-15", "user_status": 0, "user_type": "", "last_login_time": "2026-11-13 10:00:00", "register_time": "2026-11-13 09:00:00", "update_time": "2026-11-13 11:00:00", "is_deleted": 0 }
}
```

## 4. 修改密码

```
POST /api/v1/user/password
Content-Type: application/json
Authorization: Bearer <token>
```

请求体：

```json
{
  "old_password": "old123",
  "new_password": "new456"
}
```

### 4.1 校验规则

| 字段 | 校验规则 | 失败返回 |
| --- | --- | --- |
| old_password | 必填；须与库中 `password_hash` 一致 | 400 `旧密码与新密码均为必填` / 400 `旧密码不正确` |
| new_password | 必填；长度 6–10；仅允许中文、字母、数字、下划线、连字符 | 400 对应提示 |

### 4.2 响应数据

```json
{ "user_id": 1 }
```

## 5. 备注

- 当前 `password_hash` 存储与校验为明文，与现有注册/登录逻辑保持一致；若引入真实哈希（bcrypt/argon2），需连同注册、登录、改密一并改造。
- `real_name` 因需实名认证，暂不开放修改，后续接入实名流程后再纳入可改字段。
