## 时间线

### 小队相关

1. **小队成员与活动 API 方案**：最初设计 `GET /api/v1/squads/mine/overview` 一次性返回全部小队，后调整为每次只携带单个 `squad_id`。
2. **`GET /api/v1/squads/:id` 复用**：在 `getSquadDetail` 中通过动态 `import` 调用 `listActivitiesBySquads([id])` 附加该小队活动，避免循环依赖。
3. **鉴权确认**：该路径不在 `PUBLIC_PATHS` 白名单，默认已要求 token（Bearer）。
4. **成员归属校验**：新增 `assertSquadMemberAccess`，无 token→401、小队不存在→404、非队长且非在队成员→403；副队长（`member_role=2`、`member_status=1`）走成员分支放行。
5. **成员字段**：`mapMember` 输出 `id、squad_id、user_id、role、status、join_time、quit_time、remark`。
6. **成员优化**：`LIST_SQUAD_MEMBERS` 只查在队成员（`member_status=1`）；批量查 `user_profiles` 带出 `nickname`、`avatar`（`LIST_USER_PROFILES_BY_IDS` 避免 N+1）。
7. **活动字段补齐**：`mapActivity` 补 `tag_text`，与表结构一致。

### 活动相关

8. **活动详情接口**：新增 `GET /api/v1/activities/:id`（`getActivityDetail`），返回活动全部字段 + 所属小队 `squad_avatar`、`squad_name`。
9. **活动列表带小队信息**：`listActivities` 批量查 `GET_SQUADS_BY_IDS`，每条活动带 `squad_avatar`、`squad_name`。
10. **`listActivitiesBySquads` 同步**：小队详情内活动列表同样带出小队头像/名称。
11. **参与成员与人数**：新增 `LIST_ACTIVITY_MEMBERS_BY_IDS`，活动列表每条活动附 `members: [{user_id, nickname, avatar}]` 与 `member_count`（仅统计 `member_status=1`）。

### 数据库

12. **新增 `activity_member` 表**：记录参加活动的成员；因「每名小队员参加小队全部活动」，提供回填语句（`INSERT IGNORE ... SELECT` 关联 activities + squad_member）。
13. **外键错误 1215**：线上 `activities.activity_id` 为 `bigint(20) unsigned`，建表时改为同类型并修正 `activity_id` 字段。
14. **init.sql 追加**：建表置于 Squads 分组后，回填置于 Seed Data 活动区后。

### 其他 / 前端咨询

15. **注释工作**：为全部导出函数（`/** */`）与 queries.js 全部 SQL 常量添加中文说明。
16. **前端交互**：小队详情点活动跳活动详情——建议跳转后调详情接口；「先读本地缓存无则调接口」逻辑属前端 `uni` storage 范畴；PC 端成员头像无法右滑为前端交互问题，提供滚动/电容/「+N」方案。

## 关键经验（learned）

- 批量查询（`IN (...)` 去重）是避免 N+1 的最有效手段。
- 外键关联列必须两侧类型完全一致（含符号属性）。
- 动态 `import` 可规避 ESM 循环依赖。
- 成员归属校验只按 `member_status=1` 判断，不区分角色。
- 前端（小程序/PC）不在本仓库，本地缓存、横向滚动等改动需在对应前端项目进行。
